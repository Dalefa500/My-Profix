# Line Design — финансы студии

Веб-приложение для внутреннего финансового учёта дизайн-студии Line Design: проекты, клиенты,
сотрудники, приходы, расходы, зарплаты, сдельные выплаты и отчёты.

Приложением пользуются **два учредителя**. Данные хранятся **на сервере**,
оба видят одни и те же цифры. Вход — по личному коду, и код определяет
права: Шохин вносит, правит и удаляет, Ризвон только смотрит.
Сотрудникам вход не нужен — они заведены как справочник, по которому
идут расчёты.

---

## Запуск

Нужен только Node.js версии 18 или новее. Внешних библиотек нет.

```bash
node server/server.js
```

Приложение откроется по адресу `http://localhost:3000/finance/`.

Настройки через переменные окружения:

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `PORT` | порт | `3000` |
| `HOST` | адрес прослушивания | `0.0.0.0` |
| `DATA_DIR` | папка с данными | `server/data` |

### Первый вход

При первом запуске создаются две учётные записи, а коды один раз
показываются в консоли и сохраняются в файл
`server/data/КОДЫ-ДЛЯ-ВХОДА.txt`:

```
Шохин: код 123456 (полный доступ: внесение, правки, удаление)
Ризвон: код 654321 (только просмотр)
```

На экране входа вводится только код — логин не нужен. По коду приложение
понимает, кто вошёл и что ему разрешено.

Смените коды сразу после входа: **Ещё → Настройки → Код входа → Сменить**.
Имя, которым подписываются операции, меняется там же.

### Права доступа

| Роль | Что может |
|---|---|
| `admin` | вносить, изменять и удалять всё: проекты, операции, выплаты |
| `viewer` | только просматривать: кнопки изменения скрыты, а сервер отклоняет любые изменения |

Проверка прав стоит на сервере, а не только в интерфейсе: даже в обход
приложения изменить данные под кодом с ролью `viewer` нельзя.

### Управление учётными записями из командной строки

```bash
node server/manage-users.js список
node server/manage-users.js добавить <логин> "<имя>" <код> [admin|viewer]
node server/manage-users.js пароль <логин> <новый-код>
node server/manage-users.js роль <логин> admin|viewer
node server/manage-users.js удалить <логин>
```

У двух пользователей не может быть одинакового кода — иначе непонятно,
кто вошёл; при попытке задать занятый код команда откажет.

### Работа без входа

Вход можно временно отключить — приложение будет открываться сразу,
без логина и пароля:

```bash
AUTH_DISABLED=1 bash /opt/line-design-app/server/install.sh
```

Включить обратно:

```bash
AUTH_DISABLED=0 bash /opt/line-design-app/server/install.sh
```

Учётные записи и данные при переключении сохраняются. Пока вход отключён,
приложение видит и может изменить **любой, кто знает адрес сервера**, —
держать такой режим постоянно, тем более на публичном адресе, не стоит.
Имя, которым подписываются операции, в этом режиме хранится в браузере
и задаётся в «Настройках».

## Где лежат данные

| Файл в `server/data` | Что внутри |
|---|---|
| `state.json` | все данные компании |
| `users.json` | учётные записи, роли и хеши кодов |
| `sessions.json` | активные сессии входа |
| `log.jsonl` | журнал: кто и когда что менял |

Резервная копия — это просто копия папки `server/data`. Папка не попадает
в git (см. `.gitignore`).

## Как устроена синхронизация

* Любое изменение сразу применяется в браузере — интерфейс не ждёт сервер.
* Изменение уходит на сервер отдельной операцией и записывается в журнал.
* Приложение раз в 8 секунд подтягивает изменения второго учредителя,
  а также сразу после возвращения на вкладку.
* Если связь пропала, работа продолжается: операции копятся в браузере
  и отправляются, когда сеть вернётся. Состояние связи видно
  в **Настройках**.

## Разделы

| Раздел | Что показывает |
|---|---|
| **Главная** | доход, расход, прибыль за период, долг клиентов, обязательства, последние операции |
| **Проекты** | список и карточка проекта: план платежей, сдельные сотрудники, расходы, прибыль |
| **Сотрудники** | штатные (зарплата) и сдельные (оплата за м²), начислено / выплачено / остаток |
| **Финансы** | все приходы и расходы с поиском и фильтрами |
| **Отчёты** | месяц, 3 и 6 месяцев, год, произвольный период; график и таблица по месяцам |
| **Ещё → Клиенты** | клиенты, их проекты и задолженность |
| **Ещё → Платежи** | что получить от клиентов и что выплатить |
| **Ещё → Настройки** | курс доллара, правила расчёта, категории, регулярные платежи, пароль |

## Правила расчётов

1. **Площадь у каждого сотрудника своя.** Площадь проекта — только подсказка;
   в назначении на проект указывается собственный объём работы.
2. **Ставка хранится в назначении** и может отличаться от ставки сотрудника
   по умолчанию — для конкретного проекта её можно изменить.
3. **Начислено ≠ выплачено.** Начисление и факт выплаты — разные величины
   и показываются отдельно.
4. **Остаток сдельного сотрудника становится доступен только после того,
   как клиент одобрил работу** (статус проекта «Одобрен» / «Завершён»
   или этап сотрудника «Клиент одобрил»). До этого кнопка выплаты закрыта.
5. **Фактическая выплата сразу становится расходом компании** — отдельно
   вносить её не нужно. Если удалить такой расход, обязательство вернётся.
6. **Общие расходы компании не распределяются по проектам.** В прибыль
   проекта входят только сдельные выплаты и расходы, которые вы сами
   привязали к проекту.
7. **Должны получить ≠ получено**: долг клиента считается от суммы договора
   плюс запланированные дополнительные работы, минус фактические приходы.

Прибыль проекта показывается двумя числами: по договору (плановая) и
фактическая (получено минус фактически выплачено).

## Приложение на iPhone

Откройте адрес в Safari → «Поделиться» → **«На экран „Домой"»**. Приложение
запустится во весь экран, без адресной строки, со своей иконкой.

Интерфейс сделан под телефон: шапка и нижнее меню не двигаются при
прокрутке, разделы листаются пальцем влево-вправо, карточки отзываются
на нажатие. Иконка приложения — `finance/icon-180.png`, набор для
экрана «Домой» описан в `finance/manifest.webmanifest`.

## Валюты

Базовая валюта компании — **сомони (TJS)**. Ставки сотрудников часто
в долларах, поэтому у каждой операции хранятся: валюта, сумма, курс
и сумма в сомони.

Курс фиксируется в момент операции. При изменении текущего курса
**старые операции не пересчитываются** — история остаётся достоверной.

```
  storage.js            файловое хранилище
  manage-users.js       учётные записи из командной строки
```

## Размещение на сервере

Приложению нужен обычный сервер с Node.js (VDS). На GitHub Pages оно
работать не будет: там нет серверной части, а данные должны быть общими.

Пошаговая инструкция для TimeWeb: [deploy-timeweb.md](deploy-timeweb.md) —
от выбора тарифа до HTTPS и резервных копий.

Минимальный вариант — systemd-сервис:

```ini
[Unit]
Description=Line Design — финансы студии
After=network.target

[Service]
WorkingDirectory=/opt/studio-finance
ExecStart=/usr/bin/node server/server.js
Environment=PORT=3000
Environment=DATA_DIR=/var/lib/studio-finance
Restart=always

[Install]
WantedBy=multi-user.target
```

Перед публикацией в интернет поставьте впереди nginx с HTTPS: приложение
само помечает сессионную куку как защищённую, если запрос пришёл по https
(заголовок `X-Forwarded-Proto`).
